1. PRESENTATION GENERALE DU PROJET
================================================================================

La "Plateforme Interactive de Preparation au TOEIC/TOEFL" est une application
web PHP/HTML/CSS/JS concue pour les etudiants de l'Ecole Polytechnique de
Ouagadougou (EPO). Elle permet de s'entrainer aux differentes sections des
examens TOEIC et TOEFL : comprehension orale, comprehension ecrite, grammaire,
vocabulaire et expression orale.

Le projet a ete concu comme un PFA (Projet de Fin d'Annee) et est dedie au
Dr Jean ZIDA, professeur d'anglais de l'EPO.

Technologies utilisees :
- Backend : PHP 8.2 (sans framework)
- Frontend : HTML5 / CSS3 / JavaScript vanilla (aucun framework JS)
- Base de donnees : MySQL 8.x (hebergee sur Aiven Cloud)
- Hebergement : Render (conteneur Docker)
- Design : Glassmorphism, gradients sombres, Font Awesome 6, Google Fonts

3. BASE DE DONNEES (SCHEMA COMPLET)
================================================================================

Nom de la base : defaultdb (sur Aiven Cloud MySQL)
Encodage : utf8mb4_unicode_ci
10 tables au total.

TABLE : utilisateurs
--------------------
Stocke les comptes etudiants.
Colonnes :
  - ID              INT UNSIGNED AUTO_INCREMENT (cle primaire)
  - nom             VARCHAR(100) NOT NULL
  - prenons         VARCHAR(100) NOT NULL  (NB: faute d'orthographe dans le nom)
  - INE             VARCHAR(30) UNIQUE NOT NULL  (FK -> liste_ine.numero_INE)
  - classe          VARCHAR(100) NOT NULL
  - email           VARCHAR(255) UNIQUE NOT NULL
  - mot_de_passe    VARCHAR(255) NOT NULL  (hache avec password_hash/BCrypt)
  - created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  - score_total     INT UNSIGNED DEFAULT 0  (somme cumulee de tous les scores)
  - progression     DECIMAL(5,2) DEFAULT 0.00  (pourcentage 0-100)
  - rang            ENUM('Debutant','Amateur','Intermediaire','Haut Niveau',
                         'Expert','Maitre') DEFAULT 'Debutant'
  - score_palier    INT UNSIGNED DEFAULT 0  (points depuis derniere promotion)

TABLE : liste_ine
-----------------
Liste blanche des numeros INE autorises a s'inscrire.
Colonnes :
  - id              INT UNSIGNED AUTO_INCREMENT (cle primaire)
  - numero_INE      VARCHAR(20) UNIQUE NOT NULL
Donnees pre-chargees : N0001 a N0005, N111

TABLE : sessions_activite
-------------------------
Enregistre chaque session d'exercice completee.
Colonnes :
  - id              INT UNSIGNED AUTO_INCREMENT (cle primaire)
  - utilisateur_id  INT UNSIGNED (FK -> utilisateurs.ID, CASCADE)
  - type_activite   ENUM('qcm','mini_test','examen','examen_audio',
                         'examen_photos','texte_trou','prononciation')
  - score           INT UNSIGNED
  - total_questions  INT UNSIGNED
  - duree_secondes  INT UNSIGNED (nullable)
  - commence_le     TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  - termine_le      TIMESTAMP (nullable)

TABLE : resultats
-----------------
Detail des reponses individuelles par session.
Colonnes :
  - id, session_id (FK), utilisateur_id (FK), type_activite,
    question_code, reponse_donnee, est_correcte (TINYINT)

TABLE : scores_prononciation
----------------------------
Historique specifique des scores de prononciation.
Colonnes :
  - id, utilisateur_id, score (0-100), confidence (0-100),
    phrase (TEXT), enregistre_le (TIMESTAMP)

TABLE : questions_qcm (21 lignes)
TABLE : questions_mini_test (17 lignes)
TABLE : questions_texte_trou (4 lignes)
TABLE : questions_examen_audio (7 lignes)
TABLE : questions_examen_photos (6 lignes)

TABLE : comprehension_sessions
------------------------------
Scores de comprehension ecrite. FK vers utilisateurs.

TABLE : talks_sessions
----------------------
Scores du module Talks. FK vers utilisateurs.

4. SYSTEME D'AUTHENTIFICATION ET GESTION DES SESSIONS
================================================================================

Fichier : connexion.php (traitement login)
Fichier : api/config.php (demarrage session pour les API)
Fichier : api/session_check.php (middleware de verification)

FONCTIONNEMENT :
- L'utilisateur se connecte via le formulaire de interface_login.html qui
  fait un POST vers connexion.php.
- connexion.php verifie les identifiants (INE + mot de passe) contre la
  table utilisateurs. Le mot de passe est verifie avec password_verify()
  (comparaison avec le hash BCrypt stocke en base).
- En cas de succes, session_regenerate_id(true) est appele pour prevenir
  le session fixation, puis les variables de session sont definies :
    $_SESSION['authenticated'] = true
    $_SESSION['user_id'] = (int)$user['ID']
    $_SESSION['user_nom'] = $user['nom']
    $_SESSION['user_prenom'] = $user['prenons']
    $_SESSION['user_ine'] = $user['INE']
    $_SESSION['user_classe'] = $user['classe']
    $_SESSION['user_email'] = $user['email']
    $_SESSION['login_time'] = time()
- L'utilisateur est redirige vers interface_principale.php.

SECURITE DES COOKIES DE SESSION :
- lifetime: 0 (cookie de session, expire a la fermeture du navigateur)
- path: '/'
- secure: true (transmis uniquement en HTTPS)
- httponly: true (inaccessible a JavaScript)
- samesite: 'Strict' (pas envoye avec les requetes cross-site)

TIMEOUT DE SESSION (api/session_check.php) :
- Duree maximale : 4 heures (SESSION_MAX_AGE = 14400 secondes)
- Le timer est "glissant" : a chaque requete API valide, login_time est
  rafraichi a time(), ce qui prolonge la session tant que l'utilisateur
  est actif.
- Si la session depasse 4h sans activite API, elle est detruite et
  l'utilisateur recoit une erreur 401 "Session expiree".

PROTECTION DES PAGES :
- interface_principale.php, historique.php : verifient $_SESSION['authenticated']
  et redirigent vers interface_login.html si non authentifie.
- Les endpoints API (save_score.php, get_progress.php, get_history.php) :
  incluent session_check.php qui retourne JSON 401 si non authentifie.

NOTE IMPORTANTE SUR LES FETCH :
- Tous les appels fetch() vers l'API incluent credentials: 'same-origin'
  pour s'assurer que le cookie de session PHP est transmis avec la requete.
  Sans cela, PHP demarrerait une nouvelle session vide et refuserait l'acces.

5. SYSTEME D'INSCRIPTION
================================================================================

Fichier : interface_de_connexion.html (formulaire)
Fichier : inscription.php (traitement)
Style : inscriptionStyle.css

FONCTIONNEMENT :
1. L'utilisateur remplit le formulaire avec :
   - Nom, Prenom, Numero INE, Classe, Email, Mot de passe, Confirmation

2. Validation cote serveur (inscription.php) :
   - Nom : 1-100 caracteres, non vide
   - Prenom : 1-100 caracteres, non vide
   - Numero INE : 1-20 caracteres, non vide
   - Email : valide (filter_var FILTER_VALIDATE_EMAIL), max 150 car.
   - Mot de passe : minimum 6 caracteres
   - Confirmation : doit correspondre au mot de passe

3. Verification de l'INE dans la liste blanche :
   - Requete : SELECT FROM liste_ine WHERE numero_INE = :ine
   - Si l'INE n'est pas dans la liste -> erreur "INE non autorise"
   - LOGIQUE : seuls les INE pre-enregistres par un administrateur
     peuvent creer un compte. Cela empeche les inscriptions non autorisees.

4. Verification de doublon :
   - Requete : SELECT FROM utilisateurs WHERE INE = :ine
   - Si un compte existe deja -> erreur "Vous avez deja un compte"

5. Insertion :
   - Le mot de passe est hache avec password_hash($motdepasse, PASSWORD_DEFAULT)
     qui utilise BCrypt par defaut.
   - INSERT INTO utilisateurs avec rang='Debutant' et score_palier=0.

6. Feedback : popups JavaScript overlay style (pas d'alert() natif).

IMPLEMENTATION :
- Connexion DB via variables d'environnement (DB_HOST, DB_PORT, etc.)
  avec fallbacks vers localhost pour le developpement local.
- PDO avec ERRMODE_EXCEPTION, prepared statements pour prevenir les
  injections SQL.
- htmlspecialchars() sur nom/prenom pour prevenir XSS.

8. MODULE QCM (GRAMMAIRE / VOCABULAIRE)
================================================================================

Fichiers : qcm.html, qcm.js, qcmStyle.css
Donnees : questions.json (21 questions de grammaire anglaise)

TYPE D'ACTIVITE ENREGISTRE : 'qcm'

DESCRIPTION :
Quiz de grammaire/vocabulaire a choix multiples. Pas d'audio ni d'image.
Questions purement textuelles avec 3 options (A, B, C).

FLUX DE FONCTIONNEMENT :
1. Au chargement, fetch("questions.json?v=" + Date.now()) charge les 21
   questions. Le "?v=Date.now()" est un cache-buster pour eviter les
   problemes de cache navigateur.
2. Le tableau est melange aleatoirement (algorithme de Fisher-Yates via
   sort(() => Math.random() - 0.5)), puis les 15 premieres questions sont
   selectionnees.
3. displayQuestion() affiche une question a la fois :
   - Numero de question (ex: "Question 3/15")
   - Texte de la question
   - 3 boutons d'options generes dynamiquement
4. Quand l'utilisateur clique sur une option :
   - Tous les boutons sont immediatement desactives (disabled = true)
   - Si correct : le bouton prend la classe .correct (vert), score++
   - Si incorrect : le bouton prend .incorrect (rouge), et le bon bouton
     prend .correct (vert)
   - Apres 1500ms, passage automatique a la question suivante
5. A la fin des 15 questions, showScore() est appele :
   - Affiche le score final (ex: "Score : 12 / 15")
   - Appelle saveScore('qcm', score, 15) qui fait un POST vers
     api/save_score.php

STRUCTURE JSON (questions.json) :
{
  "id": "q1",
  "texte": "Which of these nouns is not countable?",
  "options": { "a": "water", "b": "animal", "c": "pen" },
  "reponse": "a"
}

NAVIGATION :
- Bouton Accueil -> interface_principale.php
- Bouton Recommencer -> window.location.reload()

9. MODULE MINI-TEST (AUDIO + IMAGE)
================================================================================

Fichiers : Mini-test.html, mini-test.js, mini-testStyle.css
Donnees : mini-test.json (17 questions avec audio et images optionnelles)

TYPE D'ACTIVITE ENREGISTRE : 'mini_test'

DESCRIPTION :
Quiz avec fichiers audio et images optionnelles. Simule l'ecoute TOEIC
avec un timer de 10 secondes apres la fin de l'audio.

FLUX DE FONCTIONNEMENT :
1. Chargement : fetch("mini-test.json?v=Date.now()"), melange, 15 premieres.
2. displayQuestion() :
   - Charge et lance automatiquement le fichier audio (q.audio)
   - Si q.image existe, affiche l'image
   - Cree les boutons d'options (A, B, C)
3. Quand l'audio se termine (audio.onended) :
   - Demarre un timer de 10 secondes
   - L'utilisateur doit repondre avant la fin du timer
4. Si le timer expire :
   - La bonne reponse est montree en vert
   - Toutes les options sont desactivees
   - Passage automatique apres 1500ms
5. Si l'utilisateur repond a temps :
   - Le timer est arrete
   - Meme logique de validation que le QCM
6. Bouton "Rejouer" (replay) : remet l'audio a 0 et le rejoue.

STRUCTURE JSON (mini-test.json) :
{
  "id": "mt1",
  "audio": "audios/audio_mt1.mp3",
  "image": "photographies/photo_mt1.jpg",    (optionnel)
  "options": { "a": "...", "b": "...", "c": "..." },
  "reponse": "b"
}

NAVIGATION :
- Bouton Accueil -> interface_principale.php
- Bouton Recommencer -> window.location.reload()

11. MODULE EXAMEN COMPLET (MULTI-PARTIES)
================================================================================

Fichiers : Examen.html, examen.js, styleExamen.css
Donnees : examen-photographies.json + examen2.json

TYPE D'ACTIVITE ENREGISTRE : 'examen'

DESCRIPTION :
Examen TOEIC simulant les differentes parties. Actuellement, seules les
parties 1 et 2 sont actives :
- Part 1 : Photographies (6 questions image + audio, 4 options A/B/C/D)
- Part 2 : Questions-Reponses (7 questions audio seul, 3 options A/B/C)
Les parties 3 a 6 sont commentees dans le code (conversations, talks,
texte a trou, comprehension).

FLUX DE FONCTIONNEMENT :
1. Configuration des parties dans un tableau :
   parts = [
     { name: "Part 1: Photographs", json: "examen-photographies.json",
       type: "image", audioDir: "audios-examen/" },
     { name: "Part 2: Question-Response", json: "examen2.json",
       type: "audio", audioDir: "audio-examen2/" }
   ]
2. loadPart(part) : charge le JSON correspondant, masque/affiche les
   sections HTML appropriees, appelle loadQuestion().
3. loadQuestion(part) :
   - Si type "image" : affiche l'image + audio, 4 options
   - Si type "audio" : affiche audio seul, 3 options
   - Timer de 27 secondes par question
   - Le timer change de couleur : <= 10s -> ambre, <= 5s -> rouge
4. validateAnswer() : arrete le timer, verifie la reponse, avance apres 1500ms.
5. Quand toutes les questions d'une partie sont terminees -> charge la
   partie suivante. Quand toutes les parties sont terminees -> showFinalScore().
6. Barre de progression : (parties_terminees / total_parties) * 100

SCORE : score / totalAnswered (ne compte que les questions effectivement repondues).

NAVIGATION : Pas de boutons Accueil/Recommencer explicites dans ce module.

16. MODULE PRONONCIATION / EXPRESSION ORALE
================================================================================

Fichiers : Orale.html, orale.js
Donnees : prononciation.json (20+ phrases)
API : api/enregistrer_score_prononciation.php (endpoint dedie)

TYPE D'ACTIVITE ENREGISTRE : 'prononciation'

DESCRIPTION :
Module le plus complexe de l'application. Utilise l'API Web Speech du
navigateur pour la reconnaissance vocale. L'utilisateur lit une phrase en
anglais a voix haute, et le systeme evalue la precision de sa prononciation.

PREREQUIS NAVIGATEUR :
- API SpeechRecognition (ou webkitSpeechRecognition)
- Fonctionne uniquement sur Chrome/Edge. Firefox et Safari non supportes.
- Si l'API n'est pas disponible, un message d'alerte est affiche et le
  module est desactive.

FLUX DE FONCTIONNEMENT :
1. Charge prononciation.json avec des phrases categoriees par difficulte
   (facile, moyen, difficile) et categorie (Daily Life, Restaurant, etc.)
2. Filtre par difficulte via les boutons .diff-btn dans #diffBar.
3. loadPhrase(idx) :
   - Affiche la phrase mot par mot (chaque mot dans un <span> neutre)
   - Affiche des badges de difficulte et categorie
   - Affiche un conseil phonetique (ex: "Focus on the 'th' sound")
4. Bouton microphone (#micBtn) :
   - Au clic, demarre SpeechRecognition avec lang: 'en-US'
   - Affiche une UI d'enregistrement (animation forme d'onde)
   - Au deuxieme clic, arrete l'enregistrement
5. recognition.onresult -> processResult(transcript, confidence) :
   - Analyse le transcript par rapport a la phrase attendue
6. ALGORITHME DE NOTATION :
   a) LCS (Longest Common Subsequence) sur les tableaux de mots normalises :
      lcsScore = (lcsLen / expectedWords.length) * 100
   b) matchWords() : compare mot a mot avec un multi-set. Chaque mot
      attendu retrouve dans le transcript est colore en vert (correct),
      les autres en rouge (incorrect). Animation de rebond echelonnee.
   c) Similarite Levenshtein : distance d'edition au niveau caractere
      entre les deux chaines normalisees. Affichee comme "Similarite texte".
   d) Note : la valeur de confidence du navigateur (Chrome) est toujours 0,
      donc le systeme utilise sa propre metrique basee sur le LCS.
7. Animation anneau circulaire SVG : remplissage progressif avec couleur
   codee (>= 80% vert, >= 50% ambre, < 50% rouge).
8. Suivi de session :
   - sessionScores[] stocke chaque tentative
   - Bande d'historique : points colores montrant le score de chaque phrase
   - Pilule de score en cours : moyenne cumulative
9. GESTION DES ERREURS DE RECONNAISSANCE :
   - Erreur reseau : jusqu'a 3 tentatives automatiques avec delai croissant
     (1.8s, 3.6s, 5.4s)
   - Erreurs specifiques : no-speech, not-allowed, audio-capture -> messages
     d'aide contextuels

SAUVEGARDE DU SCORE :
- Chaque phrase est sauvegardee individuellement via POST vers
  api/enregistrer_score_prononciation.php (endpoint DIFFERENT des autres modules)
- Corps JSON : { score, confidence, phrase, total: 100 }

ENDPOINT DEDIE (enregistrer_score_prononciation.php) :
- Cree la table scores_prononciation si elle n'existe pas (CREATE IF NOT EXISTS)
- Insere le score de prononciation
- Calcule les statistiques : moyenne, max, min, nombre de sessions
- Determine le niveau : >= 85% Expert, >= 70% Avance, >= 50% Intermediaire,
  < 50% Debutant
- Modifie dynamiquement l'ENUM de sessions_activite pour inclure 'prononciation'
- Insere egalement dans sessions_activite
- Recalcule la progression de l'utilisateur (maintenant sur 5 types au lieu de 4)

DECORATION VISUELLE :
- Particules d'arriere-plan animees sur un Canvas (60 particules, couleurs
  violet/vert, rebond sur les bords).
- Interface responsive avec grille CSS.

20. SYSTEME DE SAUVEGARDE DES SCORES (API)
================================================================================

Fichier : api/save_score.php

DESCRIPTION :
Endpoint central POST qui recoit les scores de TOUS les modules (sauf
prononciation qui a son propre endpoint).

CORPS JSON ACCEPTE :
{
  "type_activite": "qcm",        // obligatoire, dans l'ENUM
  "score": 14,                   // obligatoire, entier >= 0
  "total_questions": 15,         // obligatoire, entier > 0
  "duree_secondes": 120          // optionnel, entier >= 0
}

TYPES AUTORISES :
['qcm', 'mini_test', 'examen', 'examen_audio', 'examen_photos',
 'texte_trou', 'prononciation']

VALIDATIONS :
- Methode HTTP doit etre POST
- Corps JSON valide
- type_activite dans la liste autorisee
- score et total_questions presents
- score >= 0, total_questions > 0, score <= total_questions

OPERATIONS (dans une transaction SQL) :
1. INSERT dans sessions_activite
2. Calcul de la progression :
   - COUNT(DISTINCT type_activite) parmi les 4 types principaux
   - examen, examen_audio et examen_photos comptent tous comme "examen"
   - progression = (types_distincts / 4) * 100
3. Calcul du score_total cumule : SUM(score) de toutes les sessions
4. Logique de rang (voir section 21)
5. UPDATE utilisateurs avec les nouvelles valeurs

REPONSE JSON :
{
  "success": true,
  "session_id": 26,
  "score_total": 91,
  "progression": 100.0,
  "rang": "Debutant",
  "score_palier": 91,
  "seuil_suivant": 10000,
  "promoted": false,
  "ancien_rang": null
}

21. SYSTEME DE RANGS ET PROGRESSION
================================================================================

Fichier : api/save_score.php (logique)
Colonnes : utilisateurs.rang, utilisateurs.score_palier

DESCRIPTION :
Systeme de progression par paliers. A chaque sauvegarde de score, les points
sont ajoutes au score_palier de l'utilisateur. Quand le score_palier atteint
le seuil du rang actuel, l'utilisateur est promu au rang suivant et son
score_palier est remis a zero.

PALIERS :
  Rang actuel       |  Points requis  |  Rang suivant
  ------------------|-----------------|------------------
  Debutant          |  10 000         |  Amateur
  Amateur           |  20 000         |  Intermediaire
  Intermediaire     |  30 000         |  Haut Niveau
  Haut Niveau       |  40 000         |  Expert
  Expert            |  60 000         |  Maitre
  Maitre            |  (rang final)   |  —

LOGIQUE (dans save_score.php) :
1. Recupere rang et score_palier actuels de l'utilisateur
2. score_palier += score de la session
3. Boucle WHILE : tant que score_palier >= seuil du rang actuel :
   - score_palier -= seuil (soustrait le seuil, conserve l'excedent)
   - nouveau_rang = rang suivant
   - promoted = true
4. UPDATE utilisateurs SET rang, score_palier

La boucle while permet de gerer le cas (theorique) ou un seul score
franchit plusieurs paliers d'un coup.

REPONSE :
Le champ "promoted: true" dans la reponse JSON permet au frontend d'afficher
une notification de promotion (non encore implemente cote client).

26. RESUME DES BUGS CONNUS
================================================================================

1. comprehension-ecrite.js sauvegarde avec type_activite = 'qcm'
   au lieu d'un type dedie 'comprehension_ecrite'.
   CONSEQUENCE : les scores sont melanges avec ceux du module QCM.

2. talks.js sauvegarde avec type_activite = 'mini_test'
   au lieu d'un type dedie 'talks'.
   CONSEQUENCE : les scores sont melanges avec ceux du module Mini-test.

3. orale.js utilise un endpoint completement different
   (api/enregistrer_score_prononciation.php) avec un format de donnees
   different. Cela fonctionne mais cree une asymetrie dans l'architecture.

4. Le champ "prenons" dans la table utilisateurs est une faute
   d'orthographe (devrait etre "prenoms" ou "prenom"). C'est propague
   dans tout le code PHP.

5. Incohérence de connexion DB :
   - connexion.php, inscription.php, historique.php utilisent des
     variables d'environnement avec fallbacks vers localhost.
   - api/config.php utilise des credentials Aiven hardcodes.
   - Cela peut causer des connexions a des bases differentes en local.

6. Le bouton "Continuer avec Google" sur la page de login est un
   placeholder non fonctionnel.

7. Le module de prononciation (orale.js) ne fonctionne que sur
   Chrome/Edge. Les autres navigateurs ne supportent pas l'API
   SpeechRecognition.

8. Les credentials de la base de donnees Aiven sont hardcodes dans
   api/config.php (risque de securite si le code est public).
